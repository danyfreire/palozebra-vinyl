# Palozebra // VINYL — V0.1 prototype

A one-wheel VST3 audio effect that behaves like grabbing a spinning record.

## Interaction

- **Released:** platter runs at `1.0x`.
- **Mouse down / hold:** grabs the record and drives speed to `0`.
- **Drag clockwise / counter-clockwise:** playback speed follows angular hand velocity, including reverse.
- **Release:** the motor returns to `1.0x` and the internal read head gently catches back up to the live stream.
- **Ableton automation:** `Wheel Speed` is a published plug-in parameter. Arm automation + record, perform the scratch, then edit the recorded curve in Live.
- **Optional MIDI:** emits CC74 (channel 1) mapped from `-4x..+4x` to `0..127`. This is experimental/secondary; Ableton's normal plug-in automation is the intended recording path.

## Signal model

`Audio input -> circular history buffer -> variable-speed read head -> cubic interpolation -> output`

Pitch and time stay coupled, like physical vinyl. There is deliberately no time-stretch, crackle, vinyl EQ, or cosmetic "lo-fi" processing in V0.1.

## Build prerequisites

- CMake 3.22+
- C++20 compiler (MSVC on Windows)
- JUCE 8.0.8 checkout in `./JUCE`, **or** internet access so CMake can fetch JUCE automatically.

JUCE's official CMake docs recommend either adding JUCE as a subdirectory or installing/finding the package; this project supports the subdirectory path and a FetchContent fallback.

### Windows / Visual Studio

```powershell
# From the project directory. Optional if you want a local JUCE checkout:
git clone --depth 1 --branch 8.0.8 https://github.com/juce-framework/JUCE.git JUCE

cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --target PalozebraVinyl_VST3
```

The resulting `.vst3` bundle will be under the build tree, typically:

`build/PalozebraVinyl_artefacts/Release/VST3/Palozebra Vinyl.vst3`

Copy it to a VST3 folder scanned by Ableton, then rescan plug-ins.

## Ableton Live recording workflow

1. Put **Palozebra Vinyl** after the instrument on a MIDI track, or directly on an audio track.
2. Enable **Automation Arm** and record.
3. Open the plug-in and scratch the wheel.
4. Live records changes to **Wheel Speed** as plug-in automation.
5. Replay/edit the automation envelope. You do not need a separate audio track unless you want to print/resample the resulting audio.

For optional MIDI output, Ableton documents routing MIDI generated by a VST plug-in to another MIDI track. Whether this is useful in the audio-effect placement depends on the host routing; treat it as an experiment, not the core workflow.

## V0.1 known tradeoffs

- ~750 ms nominal history latency gives room for reverse/forward manipulation. This is intentional but too high for some live-performance uses.
- The `return-to-live` servo is a first-pass feel model; we should tune it by ear in Ableton.
- Drag sensitivity currently maps one mouse revolution/second to 1x platter speed.
- No oversampling/de-click stage yet beyond speed smoothing + cubic interpolation.

## V0.2 candidates after listening

- Low-latency / long-buffer mode switch.
- Adjustable platter inertia/torque hidden in an advanced panel.
- Better transient-safe de-clicking at extreme direction changes.
- Optional internal gesture recorder/export, if host automation is not enough.
- Hardware-controller learn / dedicated MIDI input control.
